## 演習

## 宿題

- 取り組んだレベル：発展
- やったこと：フロンティアモデルの評価に使われているベンチマークから SWE-bench Verified を選び、公式サイトと Hugging Face の Dataset Viewer で問題を確認した。作成に関わった人数と作成・検証の手順を、OpenAI のブログなどの公開情報で調べた。
- 結果：SWE-bench Verified は、実際の GitHub リポジトリの issue とその修正 PR から作られた 500 件のコーディング課題で、93 人の開発者が各件 3 名体制で検証している。採点は、修正後にテストスイートを実行し、対象テストの合否で自動判定する。今日の演習の評価セット（10 件、講師 1 人が作成し、人と LLM で採点）との違いは、規模（500 件 vs 10 件）、検証体制（93 人の開発者による多重検証 vs 講師 1 人）、採点方法（テスト実行による自動判定 vs ルーブリックに基づく人・LLM の採点）。検証で問題を落とす工程がある分、品質管理が組織的に行われている。
- 気づき・疑問：ベンチマークの信頼性は、問題の難しさだけでなく「検証に何人かけたか」で大きく変わると感じた。今日の評価セットはルーブリックの解釈によって採点がぶれる余地がある一方、SWE-bench Verified はテストで機械的に判定できる形に落とし込むことで採点のぶれをなくしている。その代わり、テストで測れる課題しか出題できないという制約もあると思う。
